# 多语言规范

**Duolo 里所有给用户看的文字都必须支持多语言，默认语言是英文。** 不只是桌面界面，也包括原生菜单、
系统授权弹窗、报错、命令行（输出和 `--help`）、终端界面（`duolo tui`）、以及写进数据里的默认值
（例如未命名任务的标题）。新增或修改任何一处文字，都要按本文同时更新所有语言。

## 支持的语言

| 代码 | 语言 | 代码 | 语言 |
|---|---|---|---|
| `en` | English（基准，默认） | `fr` | Français |
| `zh-CN` | 简体中文 | `de` | Deutsch |
| `zh-TW` | 繁體中文 | `pt-BR` | Português (Brasil) |
| `ja` | 日本語 | `ru` | Русский |
| `ko` | 한국어 | `it` | Italiano |
| `es` | Español | `tr` | Türkçe |
| `vi` | Tiếng Việt | `id` | Bahasa Indonesia |

默认跟随系统语言（`~/.duolo/settings.json` 里 `language = "auto"`），系统语言不在列表里时用英文。
用户在桌面应用的设置里切换后，命令行和终端界面也跟着变。

## 语言包只有一份

所有文案都在仓库根目录的 **`locales/<code>.json`**，桌面界面和 Rust 共用：

| 用在哪里 | 怎么取 | 键的前缀 |
|---|---|---|
| 桌面界面（`app/`） | `const t = useT(); t("key", { name })` | 按功能分：`sidebar.*`、`task.*`、`voice.*`… |
| 后端报错 | 后端返回错误码（`crates/duolo-core/src/error.rs`），界面用 `errorMessage()` 翻译 | `error.*` |
| 原生菜单 | `crates/duolo-app/src/main.rs` 的 `build_menu` | `menu.*` |
| 系统授权弹窗（麦克风、语音识别） | `build.rs` 生成 `<lang>.lproj/InfoPlist.strings` 打进应用包 | `macos.*` |
| 命令行、终端界面、引擎里的状态名 | `duolo_core::{t, tf}`；错误用 `duolo_core::error::describe` | `cli.*`、`tui.*`、`status.*`、`env.*` |

`locales/en.json` 是基准：所有键先加在这里，再补齐其他 13 种语言。

## 规则

1. **代码里不写给用户看的句子。** TypeScript 用 `t()`，Rust 用 `t()` / `tf()`。
   品牌名（Duolo、Claude、Codex、git）、快捷键符号（⌘、↵、Esc）、文件路径和命令名除外。
2. **一次补齐 14 种语言。** `pnpm build` 会运行 `app/scripts/check-i18n.mjs`，检查：
   每种语言的键和英文一致、占位符（`{name}`）一致、没有空译文，以及 Rust 代码里
   `t("…")` / `tf("…")` 用到的键都存在。TypeScript 的类型检查也会拦下缺失的键。
3. **用占位符，不拼字符串。** 写 `tf("tui.newTaskIn", &[("project", &name)])`、`t("sidebar.running", { count })`，
   不要拼接 `"New task · " + name`：不同语言语序不同。
4. **报错。** 用户能处理的错误在 `UserError` 加一个变体（`code()` + 参数），并在语言包加 `error.<code>`；
   其他内部错误用 `anyhow`、英文描述，显示时套上已翻译的 `error.internal`（"出错了：{message}"）。
5. **默认值和测试数据用英文。** 写进数据的默认值（任务标题等）用英文；测试数据用英文，
   只有专门测试中日韩等多字节字符的处理（截断、slug、输入编辑）时才用其他语言。
   断言具体文案的测试先调用 `duolo_core::i18n::set_locale("en")`。
6. **发给 Agent 的提示词**用英文写，并说明回答语言：审阅提示词的 `{language}` 换成当前语言的英文名
   （`duolo_core::i18n::language_name`）；语音整理要求"使用用户说话的语言"。
7. **语气**：简短、直接、说清楚怎么处理。中文用全角标点，按钮用动词开头（"关闭任务"）。
   能用图标表达的不加文字说明；图标按钮一定要有悬停提示（`title`），提示也要翻译。
8. **只给开发者看的内容不需要翻译**：代码注释（中文）、日志、`build.rs` 的输出、内部错误的英文详情。

## 提交前检查

- [ ] 新增或修改的每一处用户可见文字都在 `locales/en.json`，并且 14 种语言都补齐了
- [ ] 代码里没有直接写死给用户看的句子（包括 Rust 的 `println!`、`Span::raw`、`bail!` 里给用户看的部分）
- [ ] `cd app && pnpm build` 通过（含语言包检查）
- [ ] `cargo test --workspace` 通过（含 `duolo-core` 的语言包测试）

## 新增一种语言

1. 复制 `locales/en.json` 为 `locales/<code>.json`，翻译全部条目。
2. 在 `app/src/i18n/index.tsx` 的 `LOCALES` 里登记（`name` 用该语言自己的写法）；
   系统语言标签需要特殊对应时（例如 `zh-Hant` → `zh-TW`），同时改 `matchLocale()` 和
   `crates/duolo-core/src/i18n.rs` 的 `match_locale()`。
3. 在 `crates/duolo-core/src/i18n.rs` 的 `LOCALES` 和 `language_name()` 里加上这种语言。
4. 在 `crates/duolo-app/Info.plist` 的 `CFBundleLocalizations`、`build.rs` 的 `LPROJ`、
   `tauri.conf.json` 的 `bundle.resources` 里加上它的 `.lproj` 名。
5. 运行 `cd app && pnpm build` 和 `cargo test --workspace`。
